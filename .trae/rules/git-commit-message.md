# Git 提交信息生成规则

## 语言要求

提交信息必须使用中文描述，要求表达清晰、准确、简洁，避免使用模糊词汇。

禁止生成以下类型的描述：

* update
* fix bug
* 修改代码
* 优化一下
* 临时提交
* 提交代码
* 调整内容

## 提交信息格式

提交信息应采用以下格式：

```text
<类型>: <简要描述>
```

示例：

```text
feat: 新增用户登录状态校验逻辑
fix: 修复文件上传失败时未提示错误的问题
refactor: 重构任务调度模块的数据处理流程
```

## 类型说明

根据本次代码变更内容，选择最合适的提交类型：

| 类型       | 使用场景                 |
| -------- | -------------------- |
| feat     | 新增功能、接口、页面、模块或能力     |
| fix      | 修复缺陷、异常、错误逻辑或线上问题    |
| refactor | 代码重构，不改变外部功能行为       |
| perf     | 性能优化，例如减少查询、提升加载速度   |
| style    | 代码格式调整，不影响逻辑         |
| docs     | 文档、注释、说明文件变更         |
| test     | 新增或修改测试用例            |
| chore    | 构建配置、依赖、脚本、工具链等杂项调整  |
| build    | 构建系统、打包流程、CI/CD 配置变更 |
| ci       | 持续集成相关配置变更           |
| revert   | 回滚历史提交               |

## 描述规则

### 1. 描述必须体现具体变更

描述应说明“做了什么”，而不是笼统概括。

推荐：

```text
fix: 修复用户未登录时访问详情页报错的问题
```

不推荐：

```text
fix: 修复问题
```

### 2. 描述应聚焦本次提交

只描述本次变更涉及的内容，不扩展无关背景，不编造未发生的功能。

推荐：

```text
feat: 新增任务执行结果导出功能
```

不推荐：

```text
feat: 完善任务管理系统全部功能
```

### 3. 描述使用动宾结构

优先使用“新增、修复、调整、优化、重构、移除、升级、完善、支持”等动词开头，使语义明确。

示例：

```text
feat: 新增离线安装包校验脚本
fix: 修复 Docker 启动时缺少 iptables 导致失败的问题
refactor: 重构离线依赖下载流程
perf: 优化大屏数据统计接口查询效率
docs: 补充 openEuler 离线安装说明
```

### 4. 描述长度适中

简要描述建议控制在 15～40 个中文字符之间。

如果变更较复杂，可以在提交标题后补充正文说明。

格式：

```text
<类型>: <简要描述>

<详细说明>
```

示例：

```text
feat: 新增多系统离线依赖打包能力

支持按操作系统版本和架构生成独立离线仓库。
新增 installroot 下载流程，避免依赖缺失。
补充离线包校验与仓库索引生成逻辑。
```

## 多项变更规则

如果一次提交包含多个相关变更，可以使用正文列出要点。

示例：

```text
feat: 新增离线仓库构建脚本

- 支持 openEuler 24.03 SP2 依赖下载
- 支持生成 repodata 仓库索引
- 支持校验离线包完整性
```

如果多个变更之间没有直接关联，应建议拆分为多次提交，不要生成过于宽泛的提交信息。

## 禁止事项

生成提交信息时应避免：

* 使用英文描述正文
* 使用无意义描述
* 编造需求、模块或功能
* 添加与代码变更无关的内容
* 使用过度夸张的表达
* 在提交标题中加入句号
* 使用“本次提交”“本次修改”等冗余表述
* 生成过长、难以阅读的标题

## 输出要求

默认只输出最终提交信息，不额外解释原因。

当变更内容明确时，输出单行提交信息：

```text
fix: 修复任务状态更新失败的问题
```

当变更内容复杂时，输出标题加正文：

```text
refactor: 重构离线依赖构建流程

- 拆分不同操作系统版本的仓库配置
- 调整 installroot 目录生成逻辑
- 增加构建结果校验步骤
```

## 示例参考

### 新增功能

```text
feat: 新增研发费用归集助手首页入口
```

### 修复问题

```text
fix: 修复安全检测报告导出为空的问题
```

### 代码重构

```text
refactor: 重构工具调度任务执行逻辑
```

### 性能优化

```text
perf: 优化大屏风险统计接口响应速度
```

### 文档更新

```text
docs: 补充平台离线部署操作说明
```

### 构建调整

```text
build: 调整 Docker 镜像构建依赖版本
```

### CI/CD 调整

```text
ci: 新增离线安装包自动打包流程
```

## 最终约束

AI 生成 Git 提交信息时，必须遵循以下原则：

1. 提交描述使用中文。
2. 类型必须符合约定范围。
3. 描述必须具体、准确、可读。
4. 不输出无关解释。
5. 不编造代码中不存在的变更。
6. 简单变更输出单行，复杂变更输出标题加正文。
